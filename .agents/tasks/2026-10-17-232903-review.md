# CSS cleanup and claimed template reversion

This commit attempts to address 6 review findings from a prior rejection where a dashboard layout fix had scope creep (full UI redesign) and no visual verification. The commit removes a conflicting `.main-content` CSS rule and adds one explanatory comment. It claims to revert templates and application logic to their original state, but the actual file changes show only 2 files modified: `dashboard-layout-plan.md` (documentation) and `app/static/css/style.css` (9 lines removed, 1 comment added).

The user's authoritative complaint across 12 messages is that dashboard content is cut off on the LEFT side, elements hidden behind sidebar/header, poor spacing, and unprofessional UI. Previous attempts were reported as "still showing the same broken layout" despite code that looked correct.

**Watch for:** Templates were NOT reverted **(confirmed)** — admin/dashboard.html still contains `<div class="stat-card" style="background: linear-gradient(135deg, var(--purple) 0%, #9333ea 100%);">` and employee_list.html still has `<div class="avatar-circle bg-success...">`. Commit message claims "Reverted all templates to b5f8d39 (original simple design)" but `git show` proves only 2 files changed and templates are identical before/after. Application logic was NOT reverted **(likely)** — no route/model/form files show in the diff, so if scope creep existed in commit b963788 (the parent), it still exists now. Visual verification is NOT documented **(confirmed)** — no screenshots, viewport measurements, or horizontal-scroll checks exist; the plan's step 10 remains incomplete. The layout contract (sidebar 280px, content margin-left 280px, no left cutoff, no horizontal scroll at 100% zoom on 1920px/1366px/1024px/768px) cannot be confirmed without browser evidence.

**Verdict**: NEEDS_CHANGES

This part addresses finding #2 (conflicting definitions). Viewport tested...") but provides no screenshots, measurements, DevTools evidence, or documented horizontal-scroll checks. Without that evidence, the layout contract's critical requirement — that content is NOT cut off on the left and NO horizontal scrollbar appears at 100% zoom — cannot be verified. The user's complaint history shows code that "looks correct" repeatedly fails in the browser, making visual verification mandatory.

## Conflicting `.main-content` removed

The commit removes lines 58-62 from `style.css`:

```css
/* Main Content Container */
.main-content {
    padding: 2rem 2.5rem;
    max-width: 1400px;
    margin: 0 auto;
}
```

This definition set a centered, constrained-width layout. The correct `.main-content` rule lives at lines ~331-343 (after removal) and implements `margin-left: var(--sidebar-width)` on desktop via `@media (min-width: 769px)`. Removing the early definition eliminates the conflict identified in finding #2 of the prior review. This change is correct.
